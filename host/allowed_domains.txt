# =============================================================================
# TEMPLATE egress allowlist: what a NEW sandbox starts out allowed to reach.
# One domain per line. Leading dot = domain AND subdomains.
#
# Groups between `# @requires <runtime>` and `# @end` are copied into a VM's
# list only when that VM has the runtime (PTRBOX_NODE, PTRBOX_UV, PTRBOX_GO).
# A sandbox with no node cannot run npm, so granting it the npm registry
# grants a capability nothing in the VM can use - and every line here is a
# capability.
# The markers are read only in THIS file; a VM's own list is plain, with a
# note where a group was left out.
#
# Scope: `ptrbox new` copies this file into the VM's own list
# (~/.config/ptrbox/allowed_domains.d/<vm>.txt), and from then on that file
# ALONE decides that VM's egress - editing this one changes no existing
# sandbox and needs no reload, it only shapes future creates. Each group
# below says what needs it, so pruning a VM's copy down to what its project
# uses is encouraged: every entry is a capability grant, not just a
# destination.
#
# To find domains a sandbox is missing:  ptrbox logs --denied
#   (the localport= field says which VM asked; its port is in
#    ~/.lima/_generated/<vm>.proxy-port)
#
# `ptrbox install` copies this file in only if none exists yet - once
# installed, the template is yours to curate and install will report a diff
# rather than overwrite it.
# =============================================================================

# --- JavaScript, when PTRBOX_NODE is on ---
# @requires node
registry.npmjs.org         # npm/npx: your JS deps, and npx-based MCP servers
# @end

# --- Go, when PTRBOX_GO is on ---
# The module mirror and checksum database. `go build` needs neither for a
# module with no dependencies, which is why ptrbox itself builds in a sandbox
# without them - but anything with a require block does, and so does the
# toolchain switch a newer go directive triggers.
# @requires go
proxy.golang.org
sum.golang.org
# @end

# --- Python, when PTRBOX_UV is on ---
# @requires uv
pypi.org                   # package index
files.pythonhosted.org     # actual package downloads
astral.sh                  # uv's installer and self-updates
# @end

# --- GitHub / git over HTTPS ---
# Also the classic exfiltration route: anything a compromised agent can read,
# it can push somewhere that outlives the VM. Prune this group from a VM's
# copy when the project does not need GitHub.
github.com
api.github.com             # gh CLI and tooling
codeload.github.com        # tarball/zip downloads (pip-from-github uses it)
.githubusercontent.com     # raw content, release assets (uv's managed Pythons
                           #   redirect to objects.githubusercontent.com)

# --- Agent-driven browser testing (Playwright) ---
# Browser binary downloads. The matching OS libraries are baked into the VM
# template's apt list (no root post-provision, so they can't be added later).
# Playwright is driven from either runtime, and from neither there is nothing
# to drive it with - hence both names on the marker: any one of them keeps the
# group.
# @requires node uv
cdn.playwright.dev
playwright.download.prss.microsoft.com
# @end
